# Pocket Peek dependency security review

Reviewed 8 November 2026 for PR #25, local source only. No deployment, provider call, credential inspection or production database access was performed.

## Result and scope

The production audit changed from 107 reported package groups (29 high,4 critical) to 2 moderate groups, with zero high/critical groups. The full development plus production graph has 24 moderate groups and zero high/critical groups. These are npm advisory counts, not exploit counts or a claim that every attack is excluded. Full audit JSON is retained; no audit suppression or forced major upgrade was used.

Next remains pinned at 15.5.29, the current patched 15 line verified from npm metadata. Sharp remains 0.35.5. [The Server Actions advisory](https://github.com/vercel/next.js/security/advisories/GHSA-p3m5-59mp-jv5r) is patched from 15.5.28. [Next's support policy](https://nextjs.org/support-policy) currently extends security maintenance for 15 through 31 January 2027; plan the eventual framework upgrade separately.

Removed source-verified unused Genkit entry points/dependencies/scripts and unused browser Firebase initialization. Removed unused telemetry and launch/patch tooling. Active AI flows already use direct Anthropic/OpenAI SDKs. Firebase-admin remains available as a dev dependency for historical export/recovery tooling and isolated tests; it is not an active data store. Scripts that need it require a development/tooling install (`npm ci`, rather than a production-only install). No migration data or retained backups were removed.

Two deliberately bounded compatibility changes close actual dependency findings:

- Zod 3.25.76 bundled an early `zod/v4` implementation; the app's request and AI schemas already use that subpath. The latest 3 line has no advisory fix. Upgrade to 4.6.7 closes [GHSA-mrhx-c 7 xc-m 3 w 5](https://github.com/advisories/GHSA-mrhx-c7xc-m3w5). Upgrade the form resolver to compatible 5.9.2 and make input/output form types explicit. Existing kyat coercion, error wording and layouts remain the same. React Hook Form 7.62.0 already satisfies the resolver's 7.55 minimum. [Resolver migration note](https://github.com/react-hook-form/resolvers/releases/tag/v5.0.0).
- Next pins an old PostCSS8 internally. An explicit same-major override resolves all PostCSS copies to 8.5.32, also used by Tailwind and the dev tools. [The incomplete source-map fix](https://github.com/postcss/postcss/security/advisories/GHSA-fxqj-rqcc-2cmp) was patched by 8.5.23. The project does not offer user-controlled CSS compilation; this closes the package finding without asserting that the app exposed its exploit predicate.

`npm audit fix` was used without `--force` for compatible transitive updates, followed by lockfile deduplication. No independent direct SDK major was bumped. The security patches include old gRPC/HTTP/XML/crypto/archiving development transitives as well as framework build dependencies.
